## Overview

Recurring payments let you charge a payer a fixed amount on a schedule, such as a monthly subscription. You create the schedule as a Secure Payment, share its link, and the payer subscribes once on the Secure Payment page. Request Network then collects every charge automatically and pays it into your payment destination.

<Note>
Recurring payments previously ran through `POST /v2/payouts` with a `recurrence` object and the `/v2/payouts/recurring/{id}` endpoints. Those endpoints have been removed. Create schedules with `POST /v2/secure-payments` instead.
</Note>

## How it works

<Steps>
<Step title="Create the schedule">
Call [POST /v2/secure-payments](https://api.request.network/open-api/#tag/v2secure-payment/POST/v2/secure-payments) with a `recurring` object instead of `requests`. The two fields are mutually exclusive.

```json
{
  "recurring": {
    "amount": "25",
    "frequency": "monthly",
    "occurrences": 12
  },
  "reference": "subscription-pro-plan"
}
```

The schedule pays into your platform's active payment destination, or the destination bound to your Client ID. The response includes `securePaymentUrl` and `token`.
</Step>

<Step title="Share the link with the payer">
Send `securePaymentUrl` to the payer. Until a payer activates the schedule, anyone holding the link can subscribe.
</Step>

<Step title="The payer subscribes">
On the Secure Payment page, the payer connects a wallet and:

- gets a smart account, deployed for them if it does not exist yet
- approves the token allowance to that smart account, the only step that costs the payer gas
- signs two EIP-712 messages: the schedule terms and the session that performs each charge

Activation verifies both signatures and binds the payer's wallet to the schedule.
</Step>

<Step title="Charges run automatically">
Each cycle is charged when it comes due. A failing charge is retried daily up to `retryCount` times, then the schedule is suspended. Unpaid charges still get one more attempt on each later billing date. The payer can resume a suspended schedule with a full retry budget, or cancel it, from the Secure Payment page.
</Step>
</Steps>

## Schedule parameters

| Field | Required | Description |
| --- | --- | --- |
| `amount` | Yes | Amount charged each cycle, in human-readable format |
| `frequency` | Yes | `daily`, `weekly`, `monthly`, `quarterly` or `yearly` |
| `occurrences` | Yes | Number of recurring charges, from 1 to 255 |
| `startDate` | No | ISO date of the first recurring charge, today or later |
| `startDelaySeconds` | No | Seconds after the payer subscribes before the first recurring charge |
| `initialCharge` | No | One-off amount charged when the payer activates. Requires `startDate` or `startDelaySeconds`, and lowers the `occurrences` limit to 254 |
| `retryCount` | No | Daily attempts for a failing charge before the schedule is suspended, from 1 to 10. Defaults to 3 |

Omit both `startDate` and `startDelaySeconds` to charge the first cycle when the payer subscribes. `startDate` and `startDelaySeconds` are mutually exclusive.

## Tracking schedules

- **Webhooks:** Request Network sends `schedule.created`, `schedule.approved`, `schedule.suspended`, `schedule.canceled`, `schedule.completed` and `charge.failed` events to your webhook endpoints.
- **API:** [GET /v2/secure-payments/recurring/schedules](https://api.request.network/open-api/#tag/v2secure-payment/GET/v2/secure-payments/recurring/schedules) lists schedules, and [GET /v2/secure-payments/recurring/schedules/{id}](https://api.request.network/open-api/#tag/v2secure-payment/GET/v2/secure-payments/recurring/schedules/%7Bid%7D) returns every cycle, receipt and charge attempt for one schedule. Both require a wallet sign-in (SIWE) session.

## Security

The payer signs the schedule terms once, and the recurring payment contract enforces them on-chain. Charges can only go to the signed recipient, for the signed amount, on schedule and up to the signed number of cycles. Only the payer can cancel a schedule, which revokes its on-chain authority.

## Supported networks

Recurring payments are **EVM-only**.

**Mainnet:**
- Ethereum
- Arbitrum One
- Optimism
- Base
- Polygon
- BNB Smart Chain

**Testnet:**
- Sepolia

<Note>
Recurring payments are not available on Tron.
</Note>

For full endpoint schemas, see the [Request Network API Reference](https://api.request.network/open-api).
